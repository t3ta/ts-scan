# ブランチコンテキスト for feature/ts-morph-dep

## 目的

このブランチの目的は、ts-scanプロジェクトにおけるts-morph依存性の問題を解決し、より堅牢で保守性の高いアーキテクチャを構築することなのだ。具体的には、テスト環境におけるts-morphの依存関係を分離し、テストの安定性を向上させることを目指すのだ。

## ユーザーストーリー

### 解決したい課題

- 現在、`AnalyzerEngine.test.ts`など一部のテストでts-morph依存が原因で「Cannot read properties of undefined (reading 'native')」エラーが発生している
- テスト環境でts-morphの依存関係を適切に管理する方法がなく、スキップテスト（`.skip`）を多用せざるを得ない状況
- 検出器モジュールのテストがts-morphの直接呼び出しに依存しており、モック化が複雑
- 環境依存によるテストの不安定性が高く、信頼性のあるCI/CD環境の構築が困難

### 必要な機能

- ts-morphへの依存を抽象化するインターフェース層の導入
- 依存性注入（DI）パターンを活用した柔軟なコンポーネント構造
- テスト用のモックASTプロバイダーの実装
- 実際のts-morph操作を行うアダプタークラスの設計
- AST構造のスナップショットを活用したテスト手法の確立

### 期待される動作

- テスト環境でもts-morphの機能を安定して利用できる
- 現在スキップされているテストが正常に実行可能になる
- ts-morph以外のASTパーサーへの将来的な切り替えも容易になる
- テストのカバレッジと品質が向上する
- コードベースの保守性と拡張性が高まる

## 技術的な詳細

- 抽象化レイヤーの設計と実装（インターフェース定義）
- アダプターパターンを活用したts-morph操作の隠蔽
- ファクトリパターンによる実行環境に応じた実装の切り替え
- スナップショットベースのASTテスト手法の確立
- ServiceLocatorの拡張によるDIフレームワークの強化
