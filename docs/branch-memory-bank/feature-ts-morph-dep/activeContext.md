# アクティブコンテキスト for feature/ts-morph-dep

## 依存性分離における重要な考察

ts-morphに対する依存性問題の解決においては、以下の視点から捉える必要があるのだ：

1. **インフラストラクチャとドメインの分離**
   - ts-morphはTypeScriptのASTを扱うためのインフラストラクチャコンポーネント
   - 検出ロジック（ドメイン）とAST操作（インフラ）の関心を明確に分離すべき
   - ヘキサゴナルアーキテクチャ（ポート＆アダプター）のアプローチが有効

2. **テスト容易性のためのインターフェース設計**
   - テストにおける「代替可能性」を重視したインターフェース設計
   - モックとスタブによる制御可能なテスト環境の構築
   - 境界の明確化によるテストシナリオの簡素化

3. **アーキテクチャ改善の段階的アプローチ**
   - 一度に全ての依存を解消するのではなく、効果が高い箇所から段階的に改善
   - 変更の影響範囲を限定し、継続的な検証を行いながら進める
   - 既存テストの安定性を確保しつつ、新しいアプローチを導入

これらの観点を踏まえ、今後は依存性分離のパターンを適用しながら、コンポーネント間の疎結合化とテスト容易性の向上を目指すのだ。
