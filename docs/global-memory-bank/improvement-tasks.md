# 改善タスク

tags: #tasks #improvements #refactoring #performance

## 概要

このドキュメントはts-scanプロジェクトの改善点と今後取り組むべき課題をまとめたものなのだ。各領域ごとに具体的な改善タスクを整理し、プロジェクトの品質向上に役立てるのだ。

## 1. パフォーマンスの最適化

### 1.1 並列処理の導入
- **具体的なタスク**: 
  - `AnalyzerEngine.ts`に`Promise.all`を活用した並列ファイル処理を実装する
  - SourceFileの配列を複数のバッチに分割し、バッチごとに並列処理する
  - CPUコア数に基づいた最適な並列度の自動調整機能を追加する
- **期待される効果**: 大規模プロジェクトの解析時間を50%以上短縮できる
- **技術的アプローチ**: 
  ```typescript
  // 実装例
  private async analyzeFilesInParallel(files: SourceFile[]): Promise<EndpointInfo[]> {
    const batchSize = this.calculateOptimalBatchSize();
    const batches = this.createBatches(files, batchSize);
    
    const results = await Promise.all(
      batches.map(batch => this.processBatch(batch))
    );
    
    return results.flat();
  }
  ```

### 1.2 キャッシュメカニズムの実装
- **具体的なタスク**:
  - ファイルのハッシュ値を計算して変更を検出するユーティリティを実装する
  - 解析結果をローカルストレージ（JSONファイル）にキャッシュする
  - ファイル変更がない場合はキャッシュから結果を読み込む
- **期待される効果**: 増分解析の実行時間を90%削減
- **技術的アプローチ**:
  - crypto モジュールを使ったファイルハッシュ生成
  - キャッシュ管理クラスの新規作成
  - キャッシュの有効期限設定と自動クリーンアップ機能

### 1.3 解析の段階的実行
- **具体的なタスク**:
  - 「クイックスキャン」と「詳細スキャン」のモードを実装する
  - クイックスキャンでは基本的なパターンのみを検出
  - 詳細スキャンでは高度な型解析とコンテキスト解析を実行
- **期待される効果**: ユーザーが必要に応じて解析レベルを選択できるようになり、状況に応じた最適な処理が可能になる
- **コマンドライン引数の追加**:
  ```
  --scan-mode=quick|detailed
  ```

## 2. モジュール構造の改善

### 2.1 責務の明確な分離
- **具体的なタスク**:
  - `NodeExtractors.ts`と`NodeExtractorsExtended.ts`を統合・再構築する
  - AST操作機能を目的別に整理したモジュールに分割する
    - 抽出器 (Extractors)
    - 検証器 (Validators)
    - 変換器 (Transformers)
  - 共通インターフェースの設計と実装
- **期待される効果**: コードの重複を削減し、保守性と拡張性が向上する
- **リファクタリング計画**:
  1. 機能の棚卸しと分類
  2. 新しいモジュール構造の設計
  3. 段階的な移行と単体テストの作成

### 2.2 インターフェースの標準化
- **具体的なタスク**:
  - 各検出戦略の基底クラスとインターフェースを改善する
  - 共通メソッドの抽象化と標準化
  - ファクトリーメソッドパターンの導入による戦略生成の統一
- **期待される効果**: 新しい検出戦略の追加が容易になり、コード一貫性が向上する
- **インターフェース改善案**:
  ```typescript
  interface EndpointDetectionStrategy {
    readonly name: string;
    readonly priority: number;
    
    // 新しいライフサイクルメソッド
    initialize(context: DetectionContext): Promise<void>;
    detect(sourceFile: SourceFile, context: DetectionContext): EndpointInfo[];
    postProcess(endpoints: EndpointInfo[]): EndpointInfo[];
    cleanup(): Promise<void>;
  }
  ```

### 2.3 モジュールの粒度
- **具体的なタスク**:
  - 大きなファイル（特に`AxiosDetectionStrategy.ts`）を複数のモジュールに分割する
  - 各検出器(Detector)を独立したファイルとして分離する
  - ディレクトリ構造の再編成で関連コードをグループ化する
- **期待される効果**: コードの可読性向上と変更影響範囲の局所化
- **提案ディレクトリ構造**:
  ```
  src/
    detectors/
      http/
        axios/
          AxiosDetectionStrategy.ts
          detectors/
            AxiosDirectMethodCallDetector.ts
            AxiosInstanceMethodCallDetector.ts
            AxiosRequestConfigDetector.ts
          utils/
            AxiosTypeHelper.ts
  ```

## 3. エラー処理の強化

### 3.1 ロバストなエラーリカバリー
- **具体的なタスク**:
  - エラー発生時のフォールバックメカニズムを強化する
  - 解析継続のためのリカバリー戦略を実装
  - エラー詳細情報の収集と診断ヘルパーの作成
- **期待される効果**: エラーが発生しても可能な限り解析を継続し、有用な結果を提供できる
- **実装アプローチ**:
  - Try-Catch-Finallyパターンの厳格な適用
  - ロギングの強化と診断情報の充実
  - エラー発生後の状態回復メカニズム

### 3.2 エラーの分類と対応策
- **具体的なタスク**:
  - エラータイプの階層構造を定義する
    - 構文エラー (SyntaxError)
    - 型エラー (TypeError)
    - 解析エラー (AnalysisError)
    - ファイルエラー (FileError)
  - エラーごとの推奨対応策をドキュメント化
  - 重大度レベルに応じた処理を実装
- **期待される効果**: より的確なエラーメッセージとトラブルシューティングガイダンスの提供
- **エラークラス階層の例**:
  ```typescript
  class AnalysisBaseError extends Error {
    constructor(message: string, public readonly severity: ErrorSeverity) {
      super(message);
      this.name = this.constructor.name;
    }
  }

  class FileProcessingError extends AnalysisBaseError { /* ... */ }
  class TypeResolutionError extends AnalysisBaseError { /* ... */ }
  ```

## 今後の展開

これらの改善タスクは優先度順に取り組むことを推奨するのだ。特に次のフェーズでは以下の項目に注力するのだ：

1. パフォーマンス最適化（並列処理とキャッシュ）
2. モジュール構造の改善（責務分離と標準化）
3. エラー処理の強化

これにより、ツールの基盤が大幅に改善され、その後の機能追加や拡張が容易になるのだ。

各タスクの実装前には、影響範囲の評価と詳細な実装計画を作成することを推奨するのだ。また、変更はテスト駆動開発（TDD）アプローチで進め、品質を確保するのだ。
